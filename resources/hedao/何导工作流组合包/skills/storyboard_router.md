## skill_name

拆分镜技能路由


## ONE-SHOT 生成纪律（v1.24.20，P0）

**每个镜头的图片与视频，各自只准生成一次。任何模式、任何环节都不得自动重跑。**

- **禁止自动重提**：生成链路上不得出现 `for/while` 重试循环、多层重试嵌套、子进程重跑、后台自动补跑。
  提交失败（超时、502、网关抖动、读超时、轮询超时、任务 FAILED、参考图未消费）一律**即停**，把原因交导演，
  不得自动再发一次。
- **提交前必须去重**：查 `13-工作流文档/生成台账.json`，同一 `shot_id` + 媒（image/video）已有任一条提交记录
  就禁止再提交；并发时用文件锁 + 唯一 task 文件保证单一在途。
- **AI 觉得不好 ≠ 可以自己重跑**：自检或闸门复核发现风格不符、画质不佳、构图不对时，**必须停下来询问导演**
  「这一镜我不满意，是否需要授权重做（会产生一次新的付费生成）」，得到授权才可重做。
- **二次生成唯一入口**：导演逐镜显式授权，登记到 `13-工作流文档/阶段状态.json` 的
  `regeneration_authorizations`（一次一镜一媒，用完即止），登记完成才允许发起下一次。
- **批量先报备**：≥2 镜/资产的批量生成，开跑前把预计请求数（＝待生成数，**不含**任何重试系数）报给导演确认；
  运行期实际请求数超报备数即立即熔断并上报。

唯一真源：`standards/one_shot_generation_policy.json`。

## 人物朝向硬规则（v1.24.19，P0）

**人物永远不要正对镜头——身子和面部都不要对着镜头。** 凡画面中出现人物：

- **身体**：至少侧转或背向镜头，禁止正面全身、正面半身、身体正对着镜头。
- **面部**：至少偏转 30°（推荐 45°~120°）或完全不入画；禁止正脸直视镜头。
- **机位**：含人物的镜头**禁用『正面机位』**，改用『左 45° 侧面机位』『右 45° 侧面机位』『背影视角机位』，
  或仰视／俯视机位配合侧向体位。『正面机位』只允许用于无人物空镜与场景交代镜。
- **每镜必写朝向**：『画面内容』必须写明人物的身体朝向与面部朝向，推荐句式
  『她侧身对着画面外，半侧脸朝向街口，视线落在画面之外的巷子里』。
- 局部特写镜写到『面部不入画』即可；无人物空镜不适用；角色资产定妆照（三视图）不受本规则约束。
- 唯一豁免：该镜已写明『（用户要求：允许直视镜头）』并在阶段状态记录授权。

唯一真源：`standards/character_facing_policy.json`；stage4 由 `STG4-C19` 机检。
本规则同时作用于 **分镜卡 / 分镜图提示词 / 视频提示词**——图片与视频两条链都必须命中。

### common_rule_all_three

```json
"三套分镜共同遵守的台词时长规则：有台词的镜头，持续时长 ≥ ceil(台词正文字数÷5) 秒（1秒5字后再加2秒；例：10字→2秒）；无台词镜头不受该式约束。**v1.24.30 起单镜硬区间为 4-7 秒**：该式算出的时长若超过 7 秒，**不得延长时长解决，必须拆镜**（台词分载到两镜或多镜，台词正文一字不改）。三套分镜还共同遵守 `standards/group_story_arc_policy.json`（组内叙事三段式：前提→经过→结果，战斗组除外）与 `standards/group_gap_detail_shot_policy.json`（每组一个细节镜，按情绪选取）。三套分镜共享同一套标准件（组类型、景别、运镜、机位、微表情、站位、正反打、连贯性、转场、禁忌、分镜规格），标准件只在其真源处定义一次。　【v1.22.0 口径更新】三套同步执行：①**镜头组 = 一个自然段 = 讲明白一件事**，镜数不设数量上限（旧 1-3 镜上限废止；正反打组上限=说话人数+长台词反应镜；战斗组 4-6 镜）；②**运镜为六类闭集**（固定运镜 / 水平·垂直展示运镜 / 拉近运镜 / 拉远运镜 / 环绕运镜 / 跟拍运镜），每镜须写明运镜起点与终点；③固定镜头占比 **50%-60%**、单一运镜≤40%（固定豁免）、相邻同一运镜≤2镜（固定豁免）；④组内相邻两镜景别不得相同（正反打 / 连续整体展示 / 连续细节展示三豁免）；⑤场景转换过渡镜位按约 1:1 分配无人物大空镜与标准转场镜头（见 standards/transition_shot_system.json，转场镜以 `转场镜：[类型]｜` 标记写在画面内容开头）。　　【组间细节镜（v1.24.21）】三套分镜同步新增硬规则：**全片每相邻两组镜头之间必须插入一个细节镜**——景别固定**大特写**，内容为人物细节（五官/眼神/呼吸/手部/局部肢体）或场景细节（环境局部特征与质感）；该镜为独立组间镜位、不属于任何一组、不计入组的镜数与景别趋势，数量 = 镜头组总数 N − 1；『画面内容』开头标注 `组间细节镜：[人物细节|场景细节]｜` 并写焦点；细节对象取自相邻两组已有人物/场景（见 standards/group_gap_detail_shot_policy.json）。
【拆镜执行总纲（v1.21.27）】三套分镜共用同一份『拆镜执行总纲』（embedded_skills.storyboard_skill.execution_framework，真源 standards/storyboard_execution_framework.json），该总纲已由打包器注入到三套分镜技能文件顶部，逐字一致。三套无论命中哪一套，都必须先读完总纲再动手，并按总纲九步唯一工序执行：组类型、景别、机位、运镜四类字段全部是闭集，取值只能逐字取自工作流给定标准，禁止自创；禁止全片只写一种运镜、禁止全片只用一种组类型。　【场景正/反面口径（v1.21.29）】三套分镜共用同一套场景面管控口径（唯一真源 standards/shot_reverse_shot_scene_face_policy.json）：含正反打/过肩的场景必须在场景人物清单登记 face_split 六键（front_face_id / back_face_id / face_owner / camera_direction / group_binding / note），面ID 必须与 scene_id 同源（SC02→SC02_F/SC02_B），已废止 face_mapping 与中文字段写法；逐镜『场景与人物』按面标注『场景正式名·面名（面ID）』；stage5 必须为该场景两面成对生成资产 SCxx_F_v{n}.png 与 SCxx_B_v{n}.png，缺任一面即判不齐套并阻断 stage6/stage7。三套在这一点上逐项相同，不得因引擎不同而另立或放宽。"
```
