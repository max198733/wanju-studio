## skill_name

漫剧专属生图提示词标准化生成技能

## skill_description

用于生成漫剧分镜图提示词与资产提示词；分镜图提示词采用三段式固定结构『风格前缀词 + 分镜原文 + 多参数据』：①风格前缀词＝项目锁定风格库关键词组合原文，置于提示词最前；②分镜原文＝该镜分镜卡字段逐字全文保留（镜号／持续时长／机位／景别／光影／场景与人物／画面内容／运镜方式），**音效与台词字段不写入图片提示词**，画面内容与场景与人物一律逐字复制、禁止转写概括改写；③多参数据＝按「场景与人物」中的 asset_id 逐个绑定 @[asset_id]_角色资产图／@[asset_id]_场景资产图／@[asset_id]_道具资产图 并附已验证公网URL（**URL 只用于『提示词里写清绑了哪张图』；实际提交给生图接口时，必须把这 N 张参考图以 multipart 文件形式、字段名逐张重复 `image`，随 /v1/images/edits 提交——禁止把 URL 直接当 image 值传给 /v1/images/generations，该姿势会被服务端静默丢弃，见 reference_consumption_contract**） URL，绑定对象、数量与顺序与字段完全一致；内置三大类漫剧主流风格库与资产规范（白底、角色三视图），保障画面与分镜脚本零偏差、帧间画风统一

## 参考图真实消费契约（v1.24.18 强制）



- **判据唯一**：响应体 `usage.input_tokens_details.image_tokens`。**==0 即参考图未被消费**——哪怕请求体写了 image 字段、哪怕 HTTP 200、哪怕图正常返回。

- **唯一生效姿势**：`POST /v1/images/edits`，`multipart/form-data`，参考图作为**文件二进制**，**字段名 `image` 重复 N 次**（一张一个）。URL 形式在 edits 端点返回 500；文件提交到 /v1/images/generations 返回 503；`image[]` 会把同一张**双计**。

- **每镜必录**：出图后把 `image_tokens_consumed` 写进 `13-工作流文档/API任务索引.json` 对应记录，由 `gates/stage_6_image_binding_gate.py` 的 **C7** 机检。

- **整批校验**：一批里只要有一镜 image_tokens==0，即判姿势/端点用错，**整批停跑排查**，不要只重跑那一镜。

- **禁止**：以「HTTP 200 + 有图」或「参考图 URL 本机可达」当作参考已生效的证据。




## ONE-SHOT 生成纪律（v1.24.20，P0）

**每个镜头的图片与视频，各自只准生成一次。任何模式、任何环节都不得自动重跑。**

- **禁止自动重提**：生成链路上不得出现 `for/while` 重试循环、多层重试嵌套、子进程重跑、后台自动补跑。
  提交失败（超时、502、网关抖动、读超时、轮询超时、任务 FAILED、参考图未消费）一律**即停**，把原因交导演，
  不得自动再发一次。
- **提交前必须去重**：查 `13-工作流文档/生成台账.json`，同一 `shot_id` + 媒（image/video）已有任一条提交记录
  就禁止再提交；并发时用文件锁 + 唯一 task 文件保证单一在途。
- **AI 觉得不好 ≠ 可以自己重跑**：自检或闸门复核发现风格不符、画质不佳、构图不对时，**必须停下来询问导演**
  「这一镜我不满意，是否需要授权重做（会产生一次新的付费生成）」，得到授权才可重做。
- **二次生成唯一入口**：导演逐镜显式授权，登记到 `13-工作流文档/阶段状态.json` 的
  `regeneration_authorizations`（一次一镜一媒，用完即止），登记完成才允许发起下一次。
- **批量先报备**：≥2 镜/资产的批量生成，开跑前把预计请求数（＝待生成数，**不含**任何重试系数）报给导演确认；
  运行期实际请求数超报备数即立即熔断并上报。

唯一真源：`standards/one_shot_generation_policy.json`。

## 人物朝向硬规则（v1.24.19，P0）

**人物永远不要正对镜头——身子和面部都不要对着镜头。** 凡画面中出现人物：

- **身体**：至少侧转或背向镜头，禁止正面全身、正面半身、身体正对着镜头。
- **面部**：至少偏转 30°（推荐 45°~120°）或完全不入画；禁止正脸直视镜头。
- **机位**：含人物的镜头**禁用『正面机位』**，改用『左 45° 侧面机位』『右 45° 侧面机位』『背影视角机位』，
  或仰视／俯视机位配合侧向体位。『正面机位』只允许用于无人物空镜与场景交代镜。
- **每镜必写朝向**：『画面内容』必须写明人物的身体朝向与面部朝向，推荐句式
  『她侧身对着画面外，半侧脸朝向街口，视线落在画面之外的巷子里』。
- 局部特写镜写到『面部不入画』即可；无人物空镜不适用；角色资产定妆照（三视图）不受本规则约束。
- 唯一豁免：该镜已写明『（用户要求：允许直视镜头）』并在阶段状态记录授权。

唯一真源：`standards/character_facing_policy.json`；stage4 由 `STG4-C19` 机检。
本规则同时作用于 **分镜卡 / 分镜图提示词 / 视频提示词**——图片与视频两条链都必须命中。

## 单幅画面硬要求（v1.24.37，P0，防多参版式污染）

**问题**：本技能一边要求角色资产图是四格版式（三视图＋半身），一边要求分镜图把每个角色的资产图逐张垫成参考图。两条都是硬要求，但从没规定「参考图的**版式**不得搬进产出画面」——边界一缺，模型在多人镜里就照抄设定图。

**症状**（2026-10-17 S02_13 实测）：该镜是 3 人全景转场镜，多参垫了 CH03／CH02／CH01 三张角色资产图，产出直接是一张四格人物设定表（正/侧/背/半身并排），不是电影画面。同批单人镜、双人背影镜均正常，故高发条件是「多参张数≥3」与「全景/转场镜」。

**硬要求**：

1. **产出形态**：一幅完整电影画面，单一视角、单一景别、单一瞬间。
2. **禁止形态**：角色设定图／人物设定表、三视图／四视图／多角度拼图、全身与半身并排拼接、带分格线或白底抠图的证照式排布、同一个人在同一画面里多角度重复出现。
3. **必须写进【风格前缀词】段**（三套式第一段，随项目风格锁定、批量生成时不变），不得写在分镜原文段或多参数据段：
   `【单幅画面硬要求】只输出一幅完整的电影画面（单一视角、单一景别、单一瞬间），严禁输出角色设定图／三视图／四视图／多角度拼图／四格拼图／证件照排布；画面内不得出现分格线、白底抠图背景、同一个人多个角度并排、全身与半身拼接；背景必须是真实场景，不得是纯白或纯灰的影棚背景。single cinematic frame only, one viewpoint, one moment; NOT a character sheet, NOT a turnaround, NOT a four-view or multi-angle collage, NOT a grid of panels, NOT a studio cut-out on a white background.`
4. **参考图消费边界**：角色资产图只有**人脸/发型/体型/服装**参与身份一致性，其**版式不参与构图决策**；构图、景别、机位、站位与动作的唯一依据是分镜卡的『机位／景别／画面内容／运镜方式』。
5. **跑批纪律**：抽检先看多参张数最多的镜（≥3）与转场镜；发现一镜退化成设定表，**本批全部重出**，不得只补那一镜（这是模板级缺陷，补单镜会得到同批两种版式）。
6. **同样适用于 stage7 视频提示词**：视频参考图垫的也是四格资产图，视频提示词风格段必须带同一句。

真源：`standards/single_frame_output_policy.json`。
