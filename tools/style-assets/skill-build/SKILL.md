# 代码动画风格库

341 种代码动画风格，每一种都是一份可以直接用的提示词，多数还带一张参考静帧。把这个库当作**风格资料库**：先按编号或气质挑一种，再把它变成这个项目自己的动画。

## 库里有什么

- `references/catalog.json` —— 341 条的索引：编号、名称、系列、一句话说明、适合什么、标签、提示词与静帧的路径。**先查索引，不要一次读全部。**
- `assets/library/风格提示词/<系列>/<编号>_<名称>.md` —— 完整提示词。每份都含一段参考实现（Canvas 2D 的 `S.<编号>(c, w, h, t, s)`：c 是 context，w/h 是宽高，t 是秒，s 是存状态的对象），公共小工具在同目录的 `_公共函数.js`。
- `assets/library/风格提示词/<系列>/<编号>_<名称>.jpg` —— 参考静帧，193 条有图，148 条只有文字。
- `assets/library/风格挑选.html` —— 离线挑选器，在浏览器里搜索、按类筛选、勾选并导出清单。用户想看全貌时把它的路径给出去。
- `assets/library/示例/` —— 两段原始示例（B6、X7）的提示词与 HTML，看别人怎么把提示词落地。

十个系列：`A–G` 代码样片 26 · `M` 动态风格 40 · `K` 卡通画风 38 · `Z` 中国风 15 · `H` 现成版式 12 · `L` Lemo-Opuscar 59 · `V` mg-styles-15 15 · `X` code-video 31 · `R` 照参考学来的 7 · `O` 奥斯卡 98 部 98。

## 找风格

以本文件所在目录为技能目录，在它下面跑（不要假定当前工作目录）：

```bash
node scripts/styles.mjs series                    # 十个系列和条目数
node scripts/styles.mjs search 水墨               # 按关键词找
node scripts/styles.mjs search 粒子 --series AG    # 限定系列
node scripts/styles.mjs list --series Z           # 列出一个系列
node scripts/styles.mjs show B3                   # 读完整提示词
```

- **用户给了编号**：直接 `show`，保留编号和名称。
- **用户只描述气质**：给 2–3 个匹配项，说清各自的色彩、运动方式和适合的内容，再推荐一个；用户已经说「直接做」时选最匹配的往下走。
- `B6` 不在 341 条里，只在 `assets/library/示例/`，用户点名时去那里读，不要编一个索引条目。
- 148 条没有静帧：明确说是文字参考，不要虚构截图。
- 不要把几种风格的全部约束机械叠加。定一个主画风，运动方式和版式各归其位。

## 从提示词到成片

先把用户的要求提出来：内容、时长、画幅、字幕、要不要声音。缺了又不影响内容时，用 12 秒、1920×1080、30 fps、无声预览，并说明这是假设 —— **不要把无声预览说成已经配音配乐的成片。**

读选中的提示词，填掉 `{{ }}` 占位符，保住形成这个风格的核心视觉特征（配色、运动节奏、构图逻辑）。提示词里「只输出代码」之类的措辞是局部素材模板，不覆盖用户的实际交付要求。

按 OpenFilm 的规则做：

- 一个页面没有声音；画面在 `t` 秒的样子只由 `t` 决定，随机数固定种子，导出时关掉实时循环。
- 一般从 HTML + Canvas／SVG／CSS 开始；复杂的空间镜头可以用 Three.js；项目里已有 Remotion 之类的工程就沿用它。
- 用户给的数字、事实、品牌原样使用，不编造；图表形状要跟数值对得上。
- 成品留在项目里，任何文字、颜色、节奏都要能再改：常改的参数集中在一处。

## 验收与交付

打开看首帧、中段、尾帧和转场：字体、溢出、黑帧、图片加载、字幕可读性。同一个时间重复渲染结果要一样，不同时间要真的有变化。

用户要 MP4 就实际渲染，检查分辨率、时长、帧率和声音轨；缺渲染依赖时交付 HTML 和准确的运行命令，说明视频尚未导出，不能拿 HTML 当成品。

交付时说清：用了哪个编号和名称、怎么运行、规格、有没有声音。
