# 老师后台怎么部署：Railway 托管内测

核对日期：2026-10-27。已准备程序和上传目录，尚未创建云项目、购买资源或上传你的代码。

## 先明白一件事

你电脑上的老师后台已经能用，但地址 `127.0.0.1` 只代表这台电脑。要让异地学员激活、充值和扣费，账户后台必须放在持续在线的平台上。

本方案只托管小型账户与计费后台。编辑器、预览和视频导出继续在学员电脑上，图片/视频生成继续由第三方 API 完成；不是在平台上购买显卡。

## 你需要准备

1. 一个自己的 Railway 账户，以及平台接受的付款方式。不要把平台登录密码或支付资料发到对话里。
2. 一个自己的 GitHub 账户，用于网页上传私有工程并连接托管平台。也可以由开发人员通过 Railway CLI 上传本地目录，无需 GitHub。
3. 一个全新的后台管理口令，按下文的“复制云端后台口令”生成。

截至核对日，Railway 官网 Hobby 为每月最低 5 美元，含 5 美元月度资源用量，超出另计。不是每月固定 5 美元包无限量。第三方模型费用另外向各供应商支付。先做小范围内测，并在平台设置预算提醒。

先用平台提供的 HTTPS 域名测试，不必立即购买自己的域名。正式发包前，从你与学员实际网络验证访问和对话流式响应。

## 第一步：上传单独的部署目录

部署文件已整理在：

`C:\Users\openclaw\Desktop\wanju\老师后台部署包`

这个文件夹中是可公开部署的程序文件，没有你的供应商主密钥、本机账本、完整卡密或工程中的 `.local` 私有数据。

在 GitHub 新建一个 **Private（私有）** 仓库，例如 `wanju-teacher-service`，使用网页的“上传文件”功能，上传这个目录里的文件和 `public` 子目录，保持结构。

`Dockerfile`、`server.mjs`、`store.mjs`、`package.json` 应位于仓库最外层，`public/admin.html` 位于子目录内。不要把整个桌面 `wanju` 文件夹上传，也不要仅上传一个 zip。

## 第二步：Railway 创建服务

在 Railway 新建项目，选择从 GitHub 仓库部署，授权访问刚才的私有仓库并选择它。

程序已经带 Dockerfile。确认构建使用 Dockerfile，文件路径为 `Dockerfile`，根目录就是仓库根目录；启动命令使用 Dockerfile 自带命令即可。

若平台尝试先启动但报缺少管理口令或数据库权限，先完成下面的变量与存储盘，再重新部署。

## 第三步：填写运行变量

打开服务的 Variables（变量），按下表填写：

| 名称 | 值 |
| --- | --- |
| `WANJU_ADMIN_SECRET` | 双击桌面 `wanju` 中的“复制云端后台口令.cmd”，再到平台粘贴 |
| `WANJU_SERVICE_DB` | `/data/wallet.sqlite` |
| `HOST` | `0.0.0.0` |
| `PORT` | `4890` |
| `RAILWAY_RUN_UID` | `0` |

管理口令只填在平台的私密变量里，不放入 GitHub、学生安装包或截图。

“复制云端后台口令.cmd”会在首次运行时生成强随机口令并保存到本机工程 `.local/student-cloud-admin.key`。再次运行会复制同一口令，不会随便更换，避免失去已有云端数据的解密依据。

`RAILWAY_RUN_UID=0` 用于匹配 Railway 持久盘的权限要求。本机 Docker 测试仍可使用 Dockerfile 默认的 node 用户。

## 第四步：加持久化存储盘

在项目中添加 Volume（存储卷），连接到这个服务，挂载目录填：

`/data`

首次小范围内测可先申请 1 GB，再看实际账本占用调整；这只是本项目的起步建议，不是按学员人数保证的容量。

一定要有这个盘。只有容器内临时文件时，重新部署可能丢失账户与充值账本。

保持单个区域、单个实例，不启用多副本或多区域复制。目前账本使用 SQLite，不能把多个独立数据库当成一个共享余额库。

平台支持存储盘备份。开通后还要保管原管理口令；数据恢复需要数据库与原口令配套。暂时不要从老师电脑搬迁本机测试账户，先让云端以全新库上线。

## 第五步：设置检查并生成网址

在服务设置中将健康检查路径设为 `/health`。等待部署成功后，在 Settings → Networking → Public Networking 中点击 Generate Domain，目标端口使用 `4890`。

浏览器访问该 HTTPS 域名下的 `/health`，应看到包含 `ok: true`、`service: "wanju-students"` 的结果。

再访问同一域名下的 `/admin`，用第三步的云端管理口令登录老师后台。先检查账户为空、模型未启用，再生成一组专用测试激活码和充值卡。

## 第六步：让学员版连接云端

网址可以访问后，工程的 `apps/desktop/student-service.public.json` 需要填写：

```json
{
  "serviceUrl": "https://这里换成平台给你的实际域名",
  "studentEdition": true
}
```

这里只填 HTTPS 域名根地址，不追加 `/admin`、`/api` 或 `/v1`，不填任何密钥。确认后重建学员安装包并验证。

重新打包属于开发工作，可以由编程工具执行，学员不需要做。不要发当前“服务地址为空”的 0.1.1 包给异地学员。

## 第七步：小范围核账后再收费

- 先验证云端激活、登录、卡密到账、重复兑换不重复入账，以及服务重启后余额仍然存在。
- 老师在后台填写真实对话渠道、模型与售价后，先用明确授权的小额真实请求核对供应商账单。
- 当前还没有自动收款：先采用老师收款、发卡，学员兑换自动入账的流程。
- 图片、视频和音乐的统一扣费尚未接完；账户后台部署成功不等于这些素材功能已商业可用。

## 常见问题

**是否需要自己租一台传统服务器？** 不需要，可以让托管平台运行程序。平台资源仍有费用。

**老师电脑关机后能否用？** 云端部署并验证完成后，学员连接的是云端服务，不再依赖老师电脑保持开机。

**能否先不部署？** 能，本机激活与充值可用于验收，但不能让异地学员连接你的 `127.0.0.1`。

**为什么没有给我生成一个“一键部署”按钮？** 需要先有你自己的托管账户和代码仓库。目前没有代你创建账户、付费或发布程序。这个目录可以交给开发人员或编程工具继续部署。

**可以隐藏 OpenFilm 标识吗？** 主界面可改用“玩剧”名称与独立图标；上游商标说明也要求发布的改版使用自己的名称。原 MIT 版权与许可仍须随软件保留。技术名称、文件格式和内部接口不需要一起替换，以免破坏工程。
